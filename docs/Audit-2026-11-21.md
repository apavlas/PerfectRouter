# Production-Readiness Audit — 2026-11-21

**What was audited:** `main` at `c7565dd` (build 14). That's 55 app files (about 19,500 lines), 30 unit test files, and 4 UI test files.

**Baseline:** the unit tests pass, 429 of 429, on the iPhone 17 Pro simulator. The build has 9 warnings, one of which becomes an error in Swift 6. The code has no force unwraps, `try!`, `fatalError`, debug prints, or TODO comments.

**Not covered:** the UI tests (they need live MapKit), a run on a real device, and CarPlay handoff on a real head unit.

## Must fix before launch

1. **WeatherKit attribution is missing, which is an App Store rejection risk.** Apple's WeatherKit terms require the Apple Weather mark and a link to the legal attribution page wherever weather data appears. Nothing in the app shows them. Fix: use `WeatherService.shared.attribution` (mark plus legal URL) in the rain warning and anywhere else weather appears.

2. **Main thread blocks on long routes.** `RoutePlannerViewModel.swift:1643` (`driveLegsOffMain`) and `:4626` (`travelSideIndicesOffMain`) call `DispatchQueue.global().sync` from the main actor. The work runs on another thread, but the main thread waits for it the whole time, so the UI freezes anyway. The `legs` didSet at `:418` runs the first one on every route change. The comments describe this as off-main work, which it isn't, and `:6190` records the same bug being fixed somewhere else. Fix: make both calls `async` (for example with `Task.detached` and `await`, which `:2411` and `:6341` already do).

3. **Saved data can be wiped silently.** In `JSONFileStore.load()`, if the file fails to decode it returns `[]`, and the next `save()` overwrites the file. A model change in any future update that breaks decoding would erase every user's saved rides, ride history, and rider groups, and those are Pro features. Fix: when decoding fails, move the file to a `.corrupt` copy, never overwrite data that failed to load, and add a test that decodes the version 1 format.

4. **GPX import has no size cap.** `GPXCodec.decode` accepts any number of `<wpt>` waypoints. Shared links are capped at 100 (`SharedRoute.maxElementCount`), but GPX files aren't. A 400-waypoint file from another app would trigger hundreds of directions requests and get throttled by MapKit. Fix: use the same cap and tell the rider when the file is trimmed.

5. **Directions requests don't back off when throttled.** `StopSuggestionService` retries after `MKError.loadingThrottled`, but `MapKitDirectionsProvider.calculateRoutes` (`RideServices.swift:64`) doesn't. Long multi-stop rides and Twisty replans send the most directions requests. Fix: reuse the existing backoff, then confirm with a 15-stop ride.

6. **Agreed version 1 work that isn't built yet:** the StoreKit paywall and Pro gating, and the first-launch safety screen.

## Should fix before launch

7. **Saved rides are excluded from backups,** in `excludeFromBackup`, on purpose for privacy. The result is that a rider who switches phones loses every saved ride. That's at odds with selling saved-ride history as part of Pro. **This is a product decision:** I'd allow backups, since iCloud backups are encrypted, and the privacy policy would need a matching update.
8. **The App Store privacy label hasn't been checked.** `PrivacyInfo.xcprivacy` declares that no data is collected. Location leaves the device to reach MapKit and WeatherKit, and the privacy policy already says so. Check that the App Store Connect privacy answers match before submitting.
9. **Swift 6 readiness.** Mark the local function `piece` at `RoutePlannerViewModel.swift:3609` as `@Sendable`, and clear the other 8 warnings, including deprecated `MKPlacemark` initializers.
10. **The docs are out of date.** The PRD still lists lodging and twisty routing as non-goals, and the README says Xcode 15. Bring both up to date with `LaunchPlan.md`.

## After launch

11. **`RoutePlannerViewModel.swift` is 6,820 lines,** about a third of the app. It's the biggest maintenance risk, but splitting it now would put the launch at risk. Split it up after version 1 ships: fuel planning, lodging, highlights, and routing.
12. Test stubs (`UITestStubs.swift`, `UITestFixture`) ship in the release build. They're only enabled by launch arguments, so they're safe, just extra code. Wrap them in `#if DEBUG` later.
13. The unit test target's bundle ID is `com.example.PerfectRouterTests`. It's harmless but should be renamed.
